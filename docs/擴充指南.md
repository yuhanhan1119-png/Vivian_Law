# 擴充指南

這個專案預期會**一直加功能**，所以每一層都留了「註冊點」：新增功能通常只要加一段程式，
不必修改既有流程。以下依常見需求分類。

---

## 1. 新增一個命令列指令

`lawkit/cli.py`：寫一個 handler，用 `@command` 註冊，argparse 子命令與說明會自動出現。

```python
def _configure_wordcount(parser):
    parser.add_argument("law", help="法規名稱或 id")

@command("wordcount", "統計條文字數", _configure_wordcount)
def cmd_wordcount(args):
    _, store = open_store(args)
    law = resolve_law(store, args.law)
    for article in store.articles(law["id"]):
        echo(f"{article['label']}　{len(article['text'])} 字")
    store.close()
    return 0
```

慣例：

- handler 回傳結束碼（0 代表成功）
- 需要資料庫時用 `open_store(args)`；只需要路徑時用 `open_workspace(args)`
- 找法規用 `resolve_law(store, keyword)`，解析條號用 `parse_article_argument("12-1")`
- 輸出一律用 `echo()`，測試才好攔截

## 2. 新增一個 API 端點

`lawkit/server.py`：用 `@route` 註冊，回傳 `dict`／`list` 會自動轉 JSON。

```python
@route("GET", r"^/api/laws/(?P<law_id>\d+)/wordcount$")
def api_wordcount(store, match, query, body):
    law_id = int(match.group("law_id"))
    return [
        {"label": article["label"], "length": len(article["text"])}
        for article in store.articles(law_id)
    ]
```

- 參數：`store`（每個請求一個連線）、`match`（路徑比對結果）、`query`（`parse_qs` 結果）、`body`（JSON 物件或 `None`）
- 要自訂狀態碼就回傳 `(status, payload)`
- 要回傳錯誤請 `raise ApiError("訊息", 400)`
- 寫入型操作記得同時想想「離線佇列」（見第 6 點）

## 3. 新增一種匯出格式

`lawkit/exporter.py`：用 `@register` 註冊，CLI 的 `law export` 選項與 App 設定頁會自動出現。

```python
@register("anki", "Anki 匯入用 TSV（條號／條文）", ".tsv")
def to_anki(store, law_id=None):
    lines = []
    for law in ([store.get_law(law_id)] if law_id else store.list_laws()):
        for article in store.articles(law["id"]):
            lines.append(f"{law['name']} {article['label_chinese']}\t{article['text']}")
    return "\n".join(lines) + "\n"
```

## 4. 新增資料表或欄位（資料庫遷移）

`lawkit/storage.py` 的 `MIGRATIONS` 是一個 SQL 清單，索引即版本編號。

**只能在最後面追加，不可修改既有內容**，這樣舊資料庫開啟時會自動補跑新的部分。

```python
MIGRATIONS = [
    """ ...v1... """,
    """ ...v2... """,
    # v3：判解與函釋
    """
    CREATE TABLE precedents (
        id INTEGER PRIMARY KEY,
        article_id INTEGER NOT NULL REFERENCES articles(id) ON DELETE CASCADE,
        court TEXT, docket TEXT, date TEXT, summary TEXT,
        created_at TEXT NOT NULL
    );
    CREATE INDEX idx_precedents_article ON precedents(article_id);
    """,
]
```

接著在 `LawStore` 加對應方法（例如 `add_precedent()` / `list_precedents()`），
再照第 1、2 點把它接到 CLI 與 API。記得同步更新 `stats()` 與 `exporter._collect()`（若要進離線資料包）。

## 5. 調整解析或參照判斷

- **條文格式**：`lawkit/parser.py`
  - 章節標題判斷 → `_is_division_heading()`
  - 條號行判斷 → `_is_article_heading()`
  - 項／款／目 → `parse_article_body()` 內的三個 regex
  - 加新格式時，請在 `tests/test_parser.py` 補一個「不可誤判」的案例
- **引用關係**：`lawkit/crossref.py`
  - 新增關係類型 → `_RELATION_RULES`（順序即優先順序）並在 `RELATION_LABELS` 補中文
  - 法規名稱誤黏動詞 → `_LAW_PREFIX_TRIM`
  - 關係只看**同一句**的前後文，跨句不會誤判

## 6. App 前端加一個畫面

`lawkit/web/app.js`：

1. 寫一個 `async function viewXxx(match, params) { ... }`，用 `render(html)` 輸出畫面
2. 在 `routes` 陣列加一行：`[/^\/xxx$/, () => viewXxx()]`
3. 需要底部分頁就到 `index.html` 的 `.tabbar` 加一個連結，並在畫面中呼叫 `setActiveTab('xxx')`

資料存取一律走 `api.*`，它已經處理好三件事：

- 伺服器可用時走 API
- 連不上時自動改讀 IndexedDB 內的離線資料包
- 寫入型操作在離線時排入佇列，連線後 `flushPending()` 自動補送

新增寫入型操作時，照 `api.addTag` 的寫法呼叫 `mutate(path, method, body, offlineEntry)`，
並在 `applyOfflineMutation()` 補上離線時的樂觀更新。

改動 `web/` 內的檔案後，若 App 沒更新，是 Service Worker 快取造成的：
把 `sw.js` 的 `CACHE_NAME` 換一個版本號即可。

## 7. 測試

```bash
python -m unittest discover -s tests -t .
```

新增功能時的對應測試檔：

| 改哪裡 | 測試檔 |
| --- | --- |
| 解析、條號 | `tests/test_parser.py`、`tests/test_numerals.py` |
| 引用關係 | `tests/test_crossref.py` |
| 資料庫、檢索、標籤筆記 | `tests/test_storage.py` |
| 比對 | `tests/test_diff.py` |
| 匯出 | `tests/test_exporter.py` |
| 指令 | `tests/test_cli.py` |
| API 與靜態檔 | `tests/test_server.py` |

`tests/test_server.py` 會實際啟動一個伺服器並用 HTTP 呼叫，所以新增 API 後可以直接在裡面加測試。

## 8. 之後可以加的功能（構想清單）

- 判解、函釋、學說見解掛在條文底下（第 4 點的 `precedents` 範例）
- 法規樹狀目錄的收合狀態、閱讀進度
- 標籤群組與顏色管理頁
- 條文比較（不同法規的相似條文並排）
- 匯入 PDF／DOCX（先轉純文字再走既有解析）
- 全文檢索支援 AND／OR／片語與欄位限定
- 定期自動從全國法規資料庫更新（需注意對方網站的使用條款）
- 多人共用：把 SQLite 換成伺服器資料庫，或加簡單的帳號與同步
